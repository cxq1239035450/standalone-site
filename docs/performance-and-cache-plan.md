# 网站性能与缓存优化方案（可复用）

日期：2026-11-01
审查基线：`2033629`，Next.js 16.3.0 / Payload 3.88.0 / PostgreSQL / Nginx
状态：设计方案，尚未实施。依据仓库代码和框架文档；未连接生产服务器采集响应头、HAR 或性能基线，因此下文不把代码风险当成已验证的线上故障。

## 1. 目标与边界

让用户首次进入网站时只下载必要资源，再次进入时尽量复用图片、视频片段、字体和脚本。后台发布内容后，访客能够看到新版本；保存草稿不影响已发布页面。新增语言仍可运行时生效，不依赖重新构建。

本方案适用于当前网站，也可迁移至其他采用服务端渲染、CMS 和独立媒体存储的网站。通用策略放在缓存策略层，Next.js、Payload、Nginx 作为适配层，避免业务组件各自定义缓存规则。

不承诺所有资源永久不请求：首次访问、强制刷新、浏览器清理缓存、不同设备、文件更新、缓存淘汰，以及视频尚未缓存的片段都可能触发下载。网络面板有请求，也不一定重新传输了完整文件。

## 3. 先诊断：判断是否真的重复下载

在生产构建下测试，开发服务不能用于缓存效果验收。

1. 关闭开发者工具中的 Disable cache，使用同一浏览器配置和视口。
2. 首次访问首页、商品列表、详情和含视频页面，保存 HAR、截图和关键响应头。
3. 普通刷新、页面间往返、关闭标签页后重新访问，分别再次记录。
4. 检查 URL 是否完全相同，包括域名、协议、图片宽度/质量、查询参数。
5. 区分 `memory cache`、`disk cache`、304 校验、200 完整传输和视频 206 分段；不要单凭 200 状态判定全量下载。
6. 记录 `Cache-Control`、`ETag`、`Last-Modified`、`Age`、`Vary`、`Content-Length`、`Content-Range`、`x-nextjs-cache`（如存在）。
7. 逐层比较应用直连、Nginx、CDN，检查缓存头是否被覆盖或重复设置。

输出基线表：页面、设备/网络、冷/热访问、总传输字节、图片字节、视频字节、请求数、TTFB、LCP、INP、CLS、服务端查询次数。HAR 对外分享前清除 Cookie、授权信息和表单内容。

## 4. 推荐架构与缓存策略

请求路径：浏览器 → 可选 CDN → Nginx → Next.js → 公开内容读取服务 → PostgreSQL。公开媒体走独立稳定 URL；后台、预览和询盘走实时权限校验。

第一阶段只缓存公开静态资源和明确的公开数据，不对整站 HTML/RSC 设置代理强缓存，不引入 Service Worker 或 Redis。后续有多实例或流量证据时再增加共享缓存和 CDN。

下表数值为初始设计值，需根据测量调整；不是当前已生效配置。

| 对象 | 浏览器 / HTTP 策略 | 服务端策略与更新 |
| --- | --- | --- |
| 带内容指纹的 JS、CSS、字体 | `public, max-age=31536000, immutable` | 遵循框架输出；部署生成新 URL |
| 文件名含内容哈希的公开图片、视频、封面 | `public, max-age=31536000, immutable` | 新文件生成新 URL；旧文件保留至回滚/引用保留期结束 |
| 尚未版本化的 `/media`、静态业务图片 | 初期 `public, max-age=0, must-revalidate` + 校验标记 | 可返回 304；版本化前不直接缓存一年 |
| `/_next/image` | 尊重 Next 原生缓存头 | 初期显式 TTL 14400 秒，容量按磁盘测量；先完善源文件版本再延长 TTL |
| 公开页面 HTML / RSC | 初期保持框架动态响应策略 | 可复用内部公开数据，不全站覆盖响应头 |
| 商品、文章、分类公开投影 | 初期不开放通用代理 API 缓存 | 候选 TTL 300 秒 + 发布事件主动失效 + 可见性实时校验 |
| 导航、页脚、公开文案 | 随页面输出 | 候选 TTL 300 秒，按语言失效；必须校验发布与启用状态 |
| 价格、库存、询价有效性 | 不使用长期缓存作为最终依据 | 初期实时读取；表单提交时再次校验业务状态 |
| 搜索 | 初期实时查询，有界分页和输入限制 | 有证据后再加 30 秒短缓存；键包含语言、筛选、页码，限制键数量 |
| sitemap、robots、llms.txt | 初期保留动态响应，不加 CDN 长缓存 | 缓存公开计算结果，候选 TTL 60 秒；发布、撤回、SEO 改动立即失效 |
| 后台、预览、账号、询盘、邮件记录、写接口 | `private, no-store` | 不进入公共缓存 |

`no-cache` 允许存储但要求再次校验，`no-store` 禁止存储，`immutable` 适用于内容不变的 URL。规范依据：[MDN HTTP 缓存](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)、[Cache-Control](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control)。

## 5. 图片与文件版本设计

### 5.1 稳定 URL

推荐文件内容哈希命名：`/assets/media/<sha256>.<ext>`；多档图片文件名包含原文件哈希、变体宽度、格式及转换配方版本。相同文件和转换参数产生相同地址。

上传、替换文件时更新 `assetVersion`；仅修改 alt、说明、翻译时不变。记录 `assetHash`、`assetVersion`、`storageKey`（具体类型在实施时根据存储适配器确定）。不再用整条媒体记录的 `updatedAt` 判断二进制是否改变。

过渡期允许 `?v=<文件版本>`，但它不等价于不可变存储：若原路径覆盖，旧参数仍可能读到新文件。只有旧 URL 永远返回旧字节时，才可以使用一年 immutable。CDN 必须保留版本参数。

统一 URL 工具应支持相对路径、外部地址、已有参数和片段；只修改指定版本参数。不把用户相关 token 或随机时间写入公开资源 URL。外部签名 URL 使用供应商策略，不擅自追加参数。

### 5.2 图片输出

- 普通卡片默认质量从 100 调整至 75，以实际画质对比验收；细节图允许明确覆盖。
- `sizes` 使用 CSS 长度，例如 `(max-width: 640px) 100vw, (max-width: 1024px) 50vw, 33vw`；按真实卡片和容器宽度调整，不使用 `w` 描述符作为 sizes 值。
- 使用固定宽高或 aspect-ratio 防止布局移动；缩略图不加载原始大图。
- 首屏关键图使用合适的 eager / fetchPriority 或 preload；不要让所有轮播图同时抢占带宽。当前版本的 `priority` 已弃用，替换时按本地文档检查组合约束。
- 屏外图继续懒加载；图库大图在打开时加载，最多适度预取相邻图片。
- 优先复用现有 Next 图片优化，不同时叠加 CDN 动态压缩；若后续转 CDN 图片服务，明确只由一层负责转换。
- blur 占位图应小而轻；当前通用大段 base64 占位需检查重复传输与视觉收益，再选择小型独立占位或真实缩略占位。

Next 优化图片缓存有独立生命周期；延长 TTL 前必须解决文件版本切换，清理内容标签不能代替图片换 URL。参考：[Next Image](https://nextjs.org/docs/app/api-reference/components/image)。

## 6. 视频加载与传输

| 场景 | 推荐行为 |
| --- | --- |
| 产品演示、详情视频 | 封面优先；点击后挂载 source 并播放；默认 `preload="none"` |
| 首屏背景短视频 | 单个低码率短片、静音、playsInline；封面先显示；移动端或节流偏好优先静态图 |
| 屏外视频、轮播非当前项 | 不挂载 source；仅当前项或接近可视区时加载 |
| 长视频 / 多清晰度 | 第二阶段评估 HLS、自适应码率和专门媒体服务，不作为首次优化前置条件 |

统一使用媒体记录返回的 URL，支持未来对象存储，不固定拼接 `/media/filename`。加入 poster、时长、视频尺寸；MP4 处理 fast-start（元信息前置），准备常用设备可播放编码。

视频服务必须正确支持 Range、206、Content-Range、Content-Length、类型和不可变 ETag；拖动进度条不应要求先下载整个文件。不要把部分响应作为完整文件写入普通代理缓存。优先由 Nginx 静态文件服务或支持 Range 的对象存储交付，复杂分片代理缓存后置。

浏览器可能只缓存视频片段，并可能因容量回收；验收目标是减少不必要加载与可复用已缓存片段，不是保证所有视频永久离线可用。`preload` 是提示，自动播放会影响加载行为，因此需要同时控制 source 与 autoplay。参考：[MDN preload](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/preload)。

## 7. 公开内容缓存与多语言一致性

### 7.1 统一接口

建议新增 `src/cache/`，包含策略、缓存键、公开读取包装、失效事件和监控适配。业务读取仍统一经过 `src/i18n/content.ts`，不要新增另一套会语言回退的查询。

缓存键规范：`<site>:<schema-version>:<kind>:<locale>:<id-or-slug>:<query-digest>`。参数排序规范化，包含分页、筛选、排序和投影版本；不含密码、Cookie 或完整请求对象。有限标签示例：`site:<id>:lang:zh`、`content:products:42:zh`、`list:products:zh`、`navigation:zh`、`discovery:zh`。

公开缓存函数只接收规范化标量参数，只返回脱敏的已发布投影；不得把带用户/预览上下文的 Payload 读取器闭包整体缓存。预览与后台绕过共享缓存，保留权限校验。新增语言不能依赖构建期枚举。

先保留动态页面壳，在公开读取边界验证显式数据缓存是否实际命中。根据本地 Next 文档选择现有 `unstable_cache` 过渡或后续 `'use cache'`；不得假设在 force-dynamic 下添加任意 fetch 缓存都有效。启用 Cache Components 属于独立兼容性改造，不与媒体优化捆绑上线。

### 7.2 发布与失效规则

| 事件 | 需要处理的缓存 |
| --- | --- |
| 保存草稿 | 不替换、不失效公开发布快照 |
| 发布当前语言 | 该语言详情、列表、搜索、相关推荐、导航依赖、SEO 输出；其他语言详情中的语言切换可用性也需更新 |
| 修改共享业务数据 | 所有关联语言投影；实时业务字段按其策略处理 |
| 撤回 / 删除翻译 | 立即更新可见性并过期相关数据；详情404，列表/搜索/SEO剔除，其他语言切换不再提供该版本 |
| 禁用 / 删除语言 | 所有公开入口即时拒绝该语言，更新其他语言切换菜单和SEO |
| 默认语言变化 | 根入口跳转、语言注册表、默认站点配置和相关SEO |
| 改 slug / canonical | 旧新路径、列表、重定向规则、SEO；旧路径按既定跳转或404规则执行 |
| 替换媒体文件 | 生成新文件 URL，更新引用内容投影；保留旧文件用于回滚 |
| 修改媒体说明 | 失效相关语言文字投影，不更换二进制 URL |
| 定时发布 / 批量操作 / 迁移 | 与普通发布走同一事件通道，不绕过失效处理 |

事件在数据库事务成功提交后执行。建议事务内写入失效 outbox，提交后消费，带幂等键、重试、失败日志；避免事务尚未提交就刷新缓存并读回旧数据。命令行脚本不能假设具有 Next 请求缓存上下文，应经任务或认证的内部失效入口执行。

撤回与禁用不采用“先返回旧内容、后台刷新”的策略。Next 的 `revalidateTag(tag, 'max')` 有 stale-while-revalidate 行为，不适合严格撤回；需要验证 `{ expire: 0 }`、路径失效及当前运行环境支持情况。

仅靠 TTL 或异步失效不能保证立即下线：公开输出前增加实时轻量可见性检查，验证语言启用、翻译发布状态和发布修订号，列表批量检查；修订号与缓存快照不符时重新读取。将检查结果只做请求内去重，禁止跨请求复用旧权限。失效故障时仍不返回已撤回内容。已经下载到用户设备的公开内容无法远程收回。

## 8. Nginx、CDN 与部署

1. 首先盘点真实入口：`/_next/static/`、`/_next/image`、`/api/media/file/`、`/media/`、`/pet-assets/`、第三方 URL，逐个定义归属，避免遗漏直接文件访问路径。
2. 已版本化且明确公开的媒体可由 Nginx 静态交付。不要给整个 `/api/`、未知文件类型、私有附件配置 public；不存在的文件和错误响应不使用一年缓存。
3. 框架静态文件保留原生头；媒体缓存规则只针对允许的公开路径。不要同时用 expires 和多个 add_header 产生冲突的 Cache-Control。
4. `/_next/image` 若接 CDN，缓存键至少包含完整源 URL、宽度、质量，并正确区分协商图片格式、转发 Accept。未验证前不覆盖其原生缓存行为。
5. 第一阶段不做 HTML/RSC CDN 缓存。若后续开启，必须识别 Authorization、登录/预览 Cookie、Set-Cookie，并正确保留 RSC 请求头、Vary、`_rsc` 参数，避免把 HTML 返回给客户端组件导航。
6. HTML、JS、CSS、JSON、SVG 启用可用的 gzip/Brotli；图片、压缩视频不重复压缩。不得为了代理缓冲而破坏流式页面，媒体静态优化与页面流式响应分开配置。
7. 生产独立 HTTPS 入口有助于传输与现代协议使用；依据当前端口/域名条件实施，不直接占用已有服务端口。
8. 媒体共享目录继续跨 release 保留。图片缓存可使用带转换版本命名空间的独立持久目录，设置容量与清理策略；不要共享整个 `.next` 构建目录。
9. 多实例必须统一失效通知和内容版本；单机阶段不为“可能需要”而先引入 Redis。CDN 是减少回源的后续选项，不是修复浏览器缓存的前提。

## 9. 数据库、服务端与前端补充优化

- 限制列表分页、关系 depth 和返回字段；详情按需展开，避免循环请求形成 N+1。
- 对语言、主体、发布状态、slug、排序的实际查询收集执行计划，再决定复合索引；先检查现有索引，避免重复创建。
- 同一请求内共享语言注册表、导航、站点配置读取；独立查询有限并发，不无限 Promise.all 扫描全部内容。
- sitemap/llms 公共投影分批读取；内容量增长后拆分 sitemap。后台审计和草稿预览不复用公开结果。
- 服务器组件保持服务端执行；图库、视频播放器、非首屏重组件按需加载，分析实际客户端包体后再拆分。
- 字体复用现有本地字体方案，检查不需要的字重；第三方统计延后加载，避免阻塞首屏。
- 大列表控制 DOM 数量；弹窗沿用现有 loading、取消请求和错误重试，保存后仅刷新必要记录。
- 保持询盘先可靠入库、通知异步处理；缓存优化不能让邮件重试、提交结果或成功提示变成陈旧数据。

| --- | --- |
| 状态概览 | 已配置策略、最近检查时间、可取得的命中指标、磁盘占用、失效队列状态 |
| 资源检查 | 输入本站公开资源 URL，查看响应头、版本号、文件尺寸；服务端只允许本站/白名单地址，禁止任意内网探测 |
| 内容刷新 | 选择语言/内容刷新公开数据；操作完成自动更新状态 |
| 媒体处理 | 缩略图/封面生成状态、失败原因、重试；任务执行期间展示进度 |
| 操作记录 | 操作者、范围、原因、时间、结果，便于排查更新后仍显示旧内容 |

“刷新缓存”必须说明作用范围：可刷新服务端/CDN，不能清除所有访客浏览器的缓存；更换文件通过新版本 URL 实现。全站清理是低频管理操作，限流并二次确认，不放在普通保存操作里。

后台只允许选择经过校验的策略档位，不允许输入任意响应头、Nginx 指令或缓存私有数据。状态没有采集来源时显示“未接入”，不伪造命中率。相关后台持久字段需要独立数据库迁移；第一阶段只改响应头和加载方式时不需要强行增加数据库字段。

## 11. 分阶段实施与交付清单

| 阶段 | 工作 | 主要文件/交付物 | 完成标准 |
| --- | --- | --- | --- |
| P0 基线 | 生产构建测量、资源URL/响应头清单 | 脱敏HAR、性能基线、部署实况 | 能指出完整下载、校验、缓存命中的比例 |
| P1 快速优化 | 图片质量和sizes、首屏优先级、视频按需加载、旧资源协商缓存 | Media组件、URL工具、next配置、Nginx分层规则 | 复访传输减少，图片清晰度与视频播放正常 |
| P2 版本与一致性 | 文件不可变版本、发布投影缓存、可见性检查、可靠失效 | Media字段/迁移、`src/cache/`、i18n与SEO读取、事件任务 | 换图生效，草稿隔离，撤回/禁用无公开泄漏 |
| P3 运行管理 | 性能后台、监控、缓存持久化、失效失败处理 | 管理页、任务记录、部署说明 | 操作可见、有loading、失败可重试、可回滚 |

建议 P1 与 P2 分开提交和验收。不能只把缓存时间改为一年就视为完成。

## 12. 迁移与回滚

1. 备份数据库、媒体和代理配置；在数据库副本及媒体副本演练。
2. 增加可空文件版本字段，旧记录仍可读取；先部署兼容新旧结构的读取逻辑。
3. 分批计算文件哈希、复制到不可变新路径、生成变体；记录断点、校验和与失败列表，支持 dry-run 和幂等重跑。
4. 不删除、不覆盖旧文件；检测重名、缺失文件和重复文件，只有新文件校验成功才切换引用。
5. 新旧 URL 并存，先使用短缓存验证，再对不可变路径开启长期缓存；引用切换不改变主体ID、翻译或业务关联。
6. 为缓存键增加 schema/transform 版本，避免旧版本应用读入不兼容缓存；发布前清理范围有限，避免全量缓存雪崩。
7. 回滚时切回兼容应用与旧引用，关闭新增缓存策略；不要恢复数据库覆盖上线后新增询盘。不可变新资源继续保留供已加载页面使用。
8. 旧媒体清理必须晚于最长缓存期、引用检查和回滚保留期，独立执行并留审计。代理配置先 `nginx -t`，成功后再平滑加载。

## 13. 验收与性能预算

以下为初始目标，不是已测成绩；设备、网络、页面内容和统计口径固定后再比较。

| 维度 | 初始验收目标 |
| --- | --- |
| 实际用户体验 | 有足够样本后，以移动端p75检查 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1 |
| 复访媒体 | 同URL、同视口、缓存未清理时，图片重复传输字节比冷访问减少至少80%，以HAR验证 |
| 普通详情视频 | 用户未点击时视频主体传输为0；允许封面请求。明确自动播放场景单独统计 |
| 首屏负担 | 初始参考：首页首屏图片合计≤600KB，不含用户主动播放的视频；按真实视觉需求调整 |
| 数据读取 | 热请求数据库查询数和TTFB低于基线；保留必要可见性检查，不为命中率取消权限校验 |
| 内容一致性 | 发布完成后新请求读取当前发布版本；撤回/禁用后新请求不能得到旧公开内容 |
| 稳定性 | 错误率不升高，无图片404、播放失败、语言串用、表单重复提交 |

必须执行的回归：

- 中文、英文、新增日语分别冷访问与复访；同文件不同语言可复用字节，标签和正文不串语言。
- 修改alt不更换图片URL；替换文件后URL改变，新内容显示，旧URL仍对应旧字节。
- 草稿保存、发布、撤回、定时发布、删内容、禁用语言；覆盖详情、列表、搜索、相关推荐、API、语言切换、sitemap、robots与llms。
- 模拟失效任务失败、事务回滚、并发修改；不重新公开撤回内容，不留下无法恢复的旧缓存。
- 登录/匿名/预览交叉测试；询盘、邮件记录、测试邮件状态不被公共缓存复用。
- 视频首屏、屏外、点击播放、暂停、进度拖动、重复访问、移动端和节流偏好；检查206分段。
- 真实浏览器缓存场景不使用会禁用缓存的请求拦截；复用同一浏览器上下文，另用新上下文测冷访问。网络mock只用于故障与权限回归。
- 运行 lint、类型检查、相关集成测试、前后台端到端测试和生产构建；P1/P2分别留截图与前后对照。

工具可采用现有 Playwright 配合浏览器网络记录；Lighthouse用于实验室对比，真实用户指标另行采集。指标采集不记录用户表单内容。缓存容量、失效失败率、图片转换耗时、磁盘告警阈值按服务器容量确定。

## 14. 其他项目复用方式

复用时先填写以下参数，再套用策略表与验收用例，不直接照搬当前服务器路径：

```yaml
siteId: example-site
frameworkVersion: verify-installed-version
publicOrigin: https://example.com
mediaOrigin: same-origin-or-approved-cdn
storage: local-or-object-storage
deployment: single-instance-or-multiple
localesSource: runtime-language-registry
previewBoundary: authenticated-no-store
assetVersionStrategy: immutable-content-hash
cacheNamespace: public-content-v1
invalidation: post-commit-events-with-retry
visibilityPolicy: live-check-before-public-output
```

建议复用交付包由五部分组成：缓存策略模块、媒体URL与版本适配器、内容发布失效适配器、环境部署模板、冷/热访问及权限回归测试。环境密钥通过部署配置注入，不写进策略文件。

每次升级框架重新核对缓存语义、图片参数与RSC协议；TTL是可调参数，公开/私有边界、文件不可变性和撤回一致性是不可省略的规则。
