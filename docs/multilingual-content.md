# 后台多语言内容

## 日常操作

1. 打开后台 **多语言 → 语言管理**，新增 `ja` 等语言代码、显示名称、文字方向和排序。先保存准备状态。
2. 商品、文章、页面等原入口维护共享资料。保存后，在 **内容翻译** 中创建目标语言版本；也可以从一个已发布语言复制为草稿。已有目标版本不会被覆盖。
3. 在翻译记录中填写文字、富文本、SEO、行业参数或表单标签，然后预览、保存草稿或发布。发布后再编辑草稿，访客仍看到上一个已发布版本。原入口的“保存共享资料”只更新共享资料，不代表发布任意语言。
4. **前台文案** 按栏目编辑按钮、导航默认文案、图库提示、单位、公司简介等。所有必要文案及 ICU 插值变量都通过验证后才能发布。
5. 发布该语言的页头、页脚、SEO 与搜索配置，以及前台文案后，启用语言。商品关联的分类、行业模板和页面引用的表单也必须先发布对应翻译。
6. 在 **默认语言** 设置站点默认语种。默认语言不能直接禁用；语言代码不可改名，禁用语言保留数据。撤回翻译或禁用语言后，公开页面和 API 均不再返回该翻译。

商品 ID、SKU、价格、库存、分类关联、媒体文件和参数标识继续共享。图库只翻译说明，不复制文件；表单字段名称、类型、必填规则和选项值必须与共享定义一致。修改共享结构后，需要补齐相应翻译。

后台操作界面仍支持中文和英文，和内容语种分别管理。不包含自动机器翻译。

## 模型与接口

- `languages`：动态语种注册表；`language-settings.defaultLanguage`：唯一默认语种；`site-copy`：按语言独立草稿与发布的前台文案。
- `products-translations`、`posts-translations`、`pages-translations`、`categories-translations`、`media-translations`、`industry-templates-translations`、`forms-translations` 以及三个全局设置的翻译集合，均使用 `(subject, language)` 唯一索引。
- 原内容表的本地化字段和旧版本继续保留为迁移归档，公开读权限已关闭。旧文章版本不能直接恢复覆盖共享资料；新翻译使用 Payload 的独立版本及定时发布机制。
- 服务端统一使用 `src/i18n/content.ts` 的内容读取器；语言列表与文案使用 `src/i18n/service.ts`。旧 Payload `locale=zh/en` 只用于迁移归档，不是动态翻译接口。
- 公开组合接口：`GET /api/translations/content?source=products&language=ja&slug=example`。支持受控内容类型，返回共享资料与已发布翻译的合并结果；`source=header` 等读取全局设置。
- `GET /api/translations/available?path=/zh/products/example` 返回该详情可切换的已启用、已发布语种。后台创建/复制入口 `/api/translations/manage` 需要登录。
- 无翻译的商品或文章不会回退到其他语言。媒体文件可共享，但缺失的图片说明保持为空。准备中的语言仅供已登录编辑预览。

## 首次部署与数据迁移

这是一次需要数据库迁移的升级。`push: false` 禁止开发服务器自动推送表结构；不要先把新应用切到尚未迁移的生产库。

1. 暂停旧应用写入及定时任务，使用 `pg_dump --format=custom` 备份现有数据库，同时备份上传目录。在单独数据库中用 `pg_restore` 验证能够恢复；先对这个副本执行以下步骤。
2. 将该次运行的 `DATABASE_URL` 指向恢复后的副本，执行 `pnpm payload migrate`。新增迁移保留旧表和旧列，并兼容部分历史开发环境已推送的同名结构；出现未知结构差异时事务失败，不强制覆盖。
3. 执行 `pnpm migrate:languages`，只生成检查报告到已被 Git 忽略的 `.backups/`。核对 `published`、`draft`、`skip-no-translation` 和 `keep-existing` 记录；不会把中文回退值伪造为英文翻译。
4. 执行 `pnpm migrate:languages --apply --backup=C:/absolute/path/pre-migration.dump`。备份文件必须存在且非空；脚本在同一数据库事务中迁移内容、草稿与可匹配的待执行发布任务。它不会替你执行或验证 `pg_restore`。
5. 核对原 ID、关联、各语种公开内容和未发布草稿，检查报告中的跳过项目。再运行相同命令验证 `keep-existing`，确认不会覆盖已编辑的翻译。
6. 首次初始化默认启用中文。英文内容和草稿保留，但**以前没有本地化的分类、导航、媒体说明、全局品牌文字等只归入中文**；英文先保持准备状态，补齐并发布基础配置后再启用。这避免自动制造混合语言页面。后续重复执行不改变已有默认语言或启用状态。
7. 验收副本后，以同样步骤迁移正式数据库，再切换应用，恢复任务调度。Payload 定时任务仍需要部署环境周期性调用原有 jobs runner；配置迁移不会创建新的系统定时器。

迁移保留已有数据但不提供破坏性的自动 `down`。回滚时暂停写入、恢复已验证的数据库与媒体备份，再切回旧应用版本。旧归档在验收前不要清理。历史 seed 脚本仍属于旧模型，切换后不要用它们代替后台翻译编辑。

## 验证

- `pnpm exec tsc --noEmit`
- `pnpm test:languages`：字段投影、文案校验、SQL 增量迁移、实际 Payload PostgreSQL 适配器的读写、独立草稿、撤回、定时发布、禁用语言、旧内容迁移与重复执行。
- `pnpm exec vitest run --config vitest.config.mts --exclude tests/int/api.int.spec.ts`：不依赖外部数据库的相关回归测试。
- `pnpm build`
- 数据库副本准备好后设置 `LANGUAGE_E2E=1`、`LANGUAGE_E2E_EMAIL`、`LANGUAGE_E2E_PASSWORD`，运行 `pnpm test:e2e tests/e2e/language-management.e2e.spec.ts`；测试会新增独立测试语种与内容，结束时禁用测试语种。再手动核对新增日语、后台编辑、复制草稿、预览、启用、详情切换、表单提交、搜索和 sitemap。

自动测试使用独立 PGlite 内存 PostgreSQL，并经过项目真实 Payload 适配器和访问控制，不会连接或改动配置中的业务数据库。该验证不能替代真实数据库备份恢复与浏览器验收。

## 全量浏览器回归测试

测试必须使用已迁移的数据库副本。准备并发布中英文基础文案、导航、SEO 与询价表单翻译，启用英文；英文表单缺失时页面按设计不展示表单，不能当作完整英文夹具使用。商品交互测试使用 `concept-sage-nest-bed` 的英文已发布翻译和图片。

启动指向副本的生产服务后设置 `PLAYWRIGHT_BASE_URL`（例如 `http://localhost:3100`）、`PLAYWRIGHT_EXTERNAL_SERVER=1`，并让测试进程的 `DATABASE_URL` 指向同一副本。设置 `E2E_DATABASE_COPY=1` 后后台测试会创建随机账号并在结束后清理；不会删除同邮箱的现有业务账号。动态语言测试另需 `LANGUAGE_E2E=1` 以及副本编辑账号的 `LANGUAGE_E2E_EMAIL`、`LANGUAGE_E2E_PASSWORD`。

运行 `pnpm test:e2e --reporter=list --workers=2` 可覆盖全部 12 项浏览器测试。新增语种测试最终禁用其测试语种，测试内容仅保留在副本中。切换语言使用整页导航，保留当前路径、筛选参数和锚点，避免当前 Next.js 路由缓存重复拼接锚点。

2026-10-29 全量复测：lint、TypeScript、生产构建通过；18 个集成测试文件共 66 项测试通过，Chromium 浏览器测试 12 项全部通过。原库未执行迁移，以上数据库操作均针对副本。

语言管理支持删除已禁用且没有关联翻译的语言，列表和详情页均使用后台标准删除入口。默认语言不能删除；仍有关联翻译（包括草稿和前台文案）时会提示先处理关联内容，避免静默丢失数据。

后台业务列表统一使用只读详情（`mode=view`），详情中的“编辑”和勾选单条记录后的“编辑完整内容”进入原生完整表单。新建记录保持直接编辑；全局设置先显示详情。批量字段编辑入口关闭，批量删除仍按原权限执行。详情不显示密码和隐藏归档字段，编辑仍遵守原有权限、不可变字段和发布校验。

后台操作更新：业务列表最后一列固定显示“编辑、删除”，名称打开只读详情弹窗，编辑使用完整原生表单弹窗（含嵌套翻译编辑），新建也使用弹窗。保存和删除后更新当前列表，不跳离列表。默认语言仍不可删除；禁用且无业务翻译的语言可删除，并清理其基础文案、导航、SEO 及相关待执行发布计划。

删除语言弹窗提供默认未选中的“同时清空该语言的关联内容”选项。仅在明确勾选后，单条 DELETE 请求携带 `clearRelated=true`，在语言删除的同一事务中清理该语言全部业务翻译、版本和待执行计划；共享主体、库存、文件及其他语言保留。默认语言和已启用语言仍不可删除。

列表刷新修复：新增、保存及删除后使用路由刷新重新获取记录、总数和分页，保留筛选与排序。刷新期间显示 loading；详情读取和删除提交也显示加载状态。删除当前页最后一条记录时返回上一页。浏览器回归覆盖保存后的名称更新、删除后记录消失、加载提示及分页回退。
