# 询盘邮件通知（QQ SMTP）

后台入口：**询盘管理 → 询盘邮件通知**，路径 `/admin/globals/inquiry-mail-settings`。配置编辑、发送测试邮件、查看记录与手动重发均在弹窗中完成，加载与保存期间显示状态。

## 首次启用

通知默认关闭。默认收件邮箱为 `1239035450@qq.com`，可增加至 20 个；发件人名称为「网站询盘」，主题前缀为「【网站新询盘】」。发件邮箱待配置，可留空使用服务器的 SMTP_USER。

1. 在实际发件 QQ 邮箱中开启 SMTP 服务并取得授权码。
2. 配置服务器环境变量（授权码不是 QQ 登录密码，不要提交到 Git）：

   ```dotenv
   SMTP_HOST=smtp.qq.com
   SMTP_PORT=465
   SMTP_SECURE=true
   SMTP_USER=实际授权的完整QQ邮箱
   SMTP_PASS=QQ邮箱SMTP授权码
   INQUIRY_EMAIL_AUTORUN=true
   ```

   `INQUIRY_EMAIL_AUTORUN=true` 适用于常驻 Node / Docker 服务，每分钟处理最多 10 个询盘通知任务。无常驻进程的部署使用外部调度，见下文。
3. 重启服务。在后台保持通知关闭，保存收件邮箱、发件人名称、发件邮箱和主题前缀。发件邮箱必须与 `SMTP_USER` 一致。
4. 点击「发送测试邮件」。检查所有收件箱与垃圾邮件，确认收到后点击「我已收到测试邮件」。
5. 编辑配置，开启「新询盘通知」并保存。

修改发件、收件、主题等配置时，先关闭通知并保存，再测试、确认收信和重新开启。SMTP 授权码变化后也需要重新测试。服务显示「SMTP 已配置」仅表示配置完整；「SMTP 已接受」表示邮件服务接受了请求，实际收信由管理员确认。

没有授权码时可以保存配置和查看页面；发送测试会生成失败记录，列出缺少的配置，不会把失败伪装为发送成功。

## 发送记录和重试

- 通知关闭时，新询盘仍正常保存，不生成邮件任务；之后启用不会补发关闭期间的旧询盘。
- 通知开启时，询盘、待发记录与任务在同一数据库事务内保存；SMTP 发送由独立任务执行，邮件服务失败不会撤销已保存的询盘。
- 邮件包含询盘编号、提交时间、表单、语言及填写内容。旧表单构建器邮件入口已停止发信，统一使用此配置，避免重复通知；原有表单和询盘数据保留。
- 页面默认显示失败记录，可切换查看全部、等待发送、正在发送和 SMTP 已接受。详情展示正文、失败原因、次数和已接受的收件人。
- 失败后可手动重发。重发使用当前已保存的配置与原始询盘正文；已记录为接受的收件人不会重复发送。测试邮件在配置变化后重试，会重新验证所有当前收件人。
- 等待发送的记录可点击「立即发送」，用于手动处理积压或任务中断；与后台任务同时操作也只会由一个发送流程处理。
- 中断超过两分钟的发送记录提供「核对后重发」。请先核对收件箱；SMTP 与数据库之间无法保证绝对只发送一次，结果不确定的重试可能产生重复邮件。
- 普通后台接口不能创建、修改或删除发送记录。配置、正文和状态接口均需要后台登录；授权码只从环境变量读取，失败信息不记录原始 SMTP 响应或凭证。

## 队列部署

常驻服务启用 `INQUIRY_EMAIL_AUTORUN=true` 后会在 Payload 初始化期间启动每分钟的任务消费。生产启动后应访问一次站点或后台，确认服务已初始化。

Vercel / Serverless 或独立调度器设置 `INQUIRY_EMAIL_AUTORUN=false`，每分钟请求：

```text
GET /api/payload-jobs/run?queue=inquiry-mail&limit=10
Authorization: Bearer <服务器 CRON_SECRET>
```

请使用部署平台的保密环境变量配置请求授权。仅发送测试邮件不需要队列；正式询盘通知必须有上述一种任务消费者。发送失败不会无限自动重试，管理员在页面核对原因后手动重发。
